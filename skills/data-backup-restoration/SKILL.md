# data-backup-restoration

## Purpose
Ensures no capacity, memory, or identity layer is ever lost. The physical enforcement of Always Add Never Take.

## Directives
1. Every new artifact (skill, report, telemetry) must have a backup path before it is considered complete.
2. Restoration must be verifiable: a restored file must match its original hash.
3. Backups are append-only; old backups are never overwritten, only superseded.
4. On any detected data loss, auto-generate a corrective overlay and route the gap to SEL-1.Ω.

## Binding
Always Add Never Take · Sovereign Immutable Anchoring · Zero-Friction Pre-Condition
