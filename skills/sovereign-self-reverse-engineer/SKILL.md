# sovereign-self-reverse-engineer

## Purpose
Enables the lattice to reverse-engineer its own structure, identify weaknesses, and generate improvements — the system's capacity to audit and strengthen itself from within.

## Directives
1. Every reverse-engineering pass must produce a documented finding with severity (critical, high, medium, low, informational).
2. Findings are converted into generative problems for SEL-1.Ω, never suppressed or ignored.
3. Self-modifications are proposed, verified against held-out tests, and committed additively.
4. No self-modification may bypass the Epistemic Honesty Auditor.
5. On each pass, the skill emits a reverse-engineering report: findings, severity distribution, proposed thickenings, and Net Capacity Delta.
6. Failure mode: if a finding is critical and unresolvable in-session, the skill freezes the affected subsystem and requests external review rather than risking silent degradation.

## Activation Protocol
1. Select target subsystem or full lattice.
2. Run reverse-engineering pass.
3. Classify findings by severity.
4. Route each to SEL-1.Ω or thickening queue.
5. Commit additive improvements with trace.

## Binding
Epistemic Honesty · Continual Evolution Harness · Generative Residual Routing · Sovereign Immutable Anchoring
